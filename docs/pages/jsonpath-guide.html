JSONPath Locator Guide

Targeting nodes using jsonpathly queries with strict singularity guarantees.

High-Performance Destination Locators

In V6, path.jsonPath is evaluated using jsonpathly, providing powerful query expressions across nested object graphs: 

{
  "fileName": "base",
  "jsonPath": "$..*[?@.attributes['data-role'] == 'table-colgroup']",
  "filePath": ["children"],
  "action": "push"
}

The Single-Node Invariant Rule

To eliminate accidental multi-node mutations or silent write failures, resolveParent enforces that any jsonPath query must match exactly one node in the target tree: 

// Zero matches:
throw new Error(`Destination JSONPath matched no nodes: ${path.jsonPath}`);

// Multiple matches:
throw new Error(
    `Destination JSONPath must identify exactly one node; matched ${matches.length}: ${path.jsonPath}`
);

Migration from Legacy dataRole

Legacy instructions that used dataRole can seamlessly transition to jsonPath queries:

Legacy dataRole (v1 - v4) Modern JSONPathly (v5 - v6)
"dataRole": "table-header" "jsonPath": "$..*[?@.attributes['data-role'] == 'table-header']"
"dataRole": "table-body" "jsonPath": "$..*[?@.attributes['data-role'] == 'table-body']"
